貓咪選種顧問 AI Agent｜GIMBA CATZ 客戶開發專案

中央大學「AI 人工智慧導論」課程期末專題　單元 0 產出文件 學生：葉峻傑（企管系 4B，學號 111401045）

一、專案背景：

我違畢業後在新竹開了一家貓舍。表面上看，行銷漏斗運作得還算正常—— 廣告投得出去、貼文有互動、私訊每天都有人來問。但實際上，這條漏斗在最關鍵的那一段是破的。

問題的根源是一條平台規則：廣告素材裡不能出現價格。只要在 Meta 廣告上標價， 系統就會判定為活體動物販售，輕則限縮觸及，重則直接停權。 這代表我們沒辦法像一般電商那樣，在廣告端就用價格先篩掉預算不符的人——所有人都會進來， 而篩選只能發生在點擊之後，靠真人一句一句問出來。

於是每天的實況是這樣：廣告帶進一批詢問，我逐一回覆品種、花色、性格、可不可以約看貓， 聊到第五、第六句終於報出價格，然後對話就停在那裡。絕大多數的詢問，都是在報價之後瞬間死亡的。 剩下少數會說「我跟家人討論一下再約時間」，然後多半也沒有下文。 我花掉的是一整段真人工時，換回來的是一則已讀。

流量的品質也不如數據看起來漂亮。Reels 的互動數字很好看，但打開受眾輪廓會發現年齡明顯偏年輕， 跟真正有能力成交的 35 歲以上客層對不上；Threads 上純文字、不帶商品的貼文演算法表現最好， 適合累積專業聲量，卻不適合直接導購。換句話說，進來的是「看起來很多、實際上不對」的流量， 真正對的人確實藏在裡面，但得靠人工一個一個撈。

更現實的壓力來自後端：貓舍只有 18 個貓籠。空間有上限，幼貓有疫苗時程、也有適合送養的年齡窗口， 轉換速度一旦慢下來，壓力會直接反映在照護排程上。名單處理得慢，不只是少賺， 而是整個營運節奏都會被拖住。

一開始，我對這門課專題的想法其實很保守：做一個客服機器人，把重複回答的工作自動化掉， 幫自己省時間，也就是節流。跟老師討論之後方向被翻轉了——與其省下回覆熟客的時間， 不如把 AI 放到漏斗最破的那一段，去處理「陌生人怎麼變成有效名單」這件事，也就是開源。

這個專題真正要解的，是報價之前的那幾句對話。本學期先把「轉換端」做出來， 行有餘力再往前推到「廣告素材產出端」

二、產品初步構想：選種顧問 Agent

一個放在網站 / LINE 官方帳號上的互動式對話工具，讓還不認識 GIMBA CATZ 的陌生訪客， 透過幾個簡單問題，被引導找到「適合自己的貓」，並在過程中自然留下聯絡方式與需求， 讓貓舍後續有名單可以主動開發，而不是被動等客人私訊詢價。

核心功能：

多輪問答收集訪客條件：居住空間大小、家中是否有小孝或其他寵物、過敏史、 想要親人型還是獨立型個性、預算範圍、預計何時想接貓回家
依貓舍現有貓咪資料（品種特性、個性描述、現況）做配對推薦
對於已成功配對、明確表態有興趣的訪客，自動整理其需求摘要並留存聯絡資訊
遇到超出知識庫範圍的問題（例如醫療糾紛、退換貨爭議、殺價要求）時， 依 guardrail 規則收斂回覆或轉交真人客服，不隨意承諾

三、使用場景（User Journey）
訪客在 Instagram / Facebook 貼文留言或私訊詢問「請問還有貓嗎？」
Agent 判斷這是有興趣的詢問，開始多輪對話，逐步詢問空間、經驗、預算等條件
Agent 從知識庫（貓咪品種資料、現有貓咪清單、貓舍政策）中檢索相關資訊， 生成客製化的配對建議與說明
對話尾聲，Agent 整理出一份「訪客需求摘要 + 聯絡方式」，存入名單（表單 / 試算表）
貓舍主人定期查看名單，主動聯繫、安排看貓或簽約

四、部署管道優先順序

原規劃部署在 LINE 官方帳號，但重新檢視後發現：目前的流量入口是 Meta 廣告 → IG/FB 留言或私訊， 若要求訪客額外跳轉去開 LINE，中間會有一次不必要的平台切換，流失掉一部分本來就是低涉入的冷流量。 因此部署管道調整為：

第一優先：Meta Messenger / Instagram 私訊——agent 直接接在訪客留言、私訊的原生介面上， 不需要額外跳轉，最貼合現有廣告導流的行為路徑。
第二優先：網站嵌入式聊天視窗——若廣告改導向 landing page，agent 以嵌入式聊天呈現， 同樣不需跳轉 App，且介面完全自己掌控。
後段關係維護：LINE 官方帳號——留給已經透過 agent 對話、確認有興趣的「熱名單」， 用「加 LINE 領取專屬貓咪照片 / 優先看貓通知」等明確誘因邀請加入，用於約時間、提醒、老客戶再行銷， 不作為第一接觸點。

五、技術路線

本學期選定使用Claude Code推薦的 Dify（開源 LLM 應用開發平台）取代課程預設的 Coze：

介面同樣是拖拉式 workflow，學習曲線與 Coze 類似
內建知識庫（RAG）、Plugin/Tool、對話記憶（Memory）、Guardrail 等模組， 對應課綱單元 2～8 的知識點都有現成功能可以練習
開源、可自架，之後若要串接 LINE 官方帳號或自有網站也有彈性
